  VAPEFREE — COISAS PARA FAZER

---- BUGS / FIXES ----

[ ] Corrigir lógica de streak
    Hoje o calcStreak() conta qualquer dia que tenha um registro,
    mas um dia onde o usuário não abriu o app quebra o streak mesmo
    que ele não tenha usado. A lógica precisa distinguir:
      - Dia sem registro algum = streak mantido (correto)
      - Dia com registro de "não usei" = streak mantido (correto)
      - Dia com registro de "usei" = streak quebrado (correto)
    Revisar se o campo `used` está sendo salvo e lido corretamente
    em todos os fluxos do RegisterScreen.

[ ] checkAchievements() não é async mas deveria ser
    A função em achievements.js é síncrona mas o restante da base
    é toda async/await. Isso cria inconsistência e pode causar
    comportamento estranho em fluxos que fazem await nela.
    Padronizar para async e ajustar os pontos que a chamam.

[ ] Conquistas não persistem o estado "desbloqueado" corretamente
    O checkAchievements() recalcula tudo do zero toda vez que a
    tela é aberta, em vez de ler o estado salvo. Uma conquista
    desbloqueada pode parecer bloqueada se os dados mudarem.
    Usar getAchievements() como fonte de verdade e só recalcular
    conquistas ainda não desbloqueadas.

[ ] Streak conta "dias com registro" em vez de "dias consecutivos"
    O loop em calcStreak itera datas no sentido passado → presente
    mas usa includes() em um array não garantidamente ordenado.
    Refatorar para garantir ordenação e checar sequência real
    de dias (hoje, ontem, anteontem...).

---- GAMIFICAÇÃO ----

[ ] Sistema de XP e nível do usuário
    Cada ação gera XP. Sugestão de tabela:
      - Fazer um registro: +10 XP
      - Dia sem usar: +30 XP
      - Desbloquear conquista: +50 XP (Exemplo, cada conquista deve ter uma quantia de XP diferente baseada na sua dificuldade)
      - Completar missão diária: +40 XP
      - Streak de 7 dias: +100 XP bônus
    Níveis sugeridos:
      0–199 XP     → Iniciante
      200–499 XP   → Resistente
      500–999 XP   → Guerreiro
      1000–1999 XP → Campeão
      2000+ XP     → Lendário
    Exibir barra de progresso de XP na HomeScreen, abaixo das stats.
    Salvar xp e level no storage junto com os outros dados do usuário.

[ ] Missões diárias e semanais
    Lista de missões que renovam periodicamente. Exemplos diários:
      - "Faça seu registro de hoje"
      - "Não use o vape hoje"
      - "Leia a dica do dia"
    Exemplos semanais:
      - "Complete 5 dias sem usar nesta semana"
      - "Faça registros em 7 dias seguidos"
      - "Economize R$ 10 esta semana"
    Cada missão concluída dá XP e pode desbloquear conquistas.
    Criar tela ou card na Home listando as missões do dia.

[ ] Celebração visual ao desbloquear conquista
    Hoje o desbloqueio acontece silenciosamente.
    Implementar um modal que aparece automaticamente com:
      - Emoji/ícone grande da conquista
      - Nome e descrição
      - Animação (confete, brilho, ou vibração via Haptics)
      - Botão "Arrasou!" para fechar
    Disparar após saveRecord() quando newUnlocks.length > 0.

[ ] Mais conquistas para cobrir novos comportamentos
    As 12 atuais são boas mas focadas em streaks e economia.
    Adicionar conquistas para:
      - Primeira missão concluída
      - Usar a técnica de respiração 5 vezes
      - Identificar o mesmo trigger 3 vezes (autoconhecimento)
      - Abrir o app 7 dias seguidos
      - Completar o tutorial
      - Economia de R$ 500 e R$ 1000

[ ] Streak com "escudo" (proteção de 1 dia)
    Mecânica comum em apps de gamificação (Duolingo, etc).
    O usuário ganha 1 escudo após 7 dias de streak.
    Se esquecer de registrar um dia, o escudo é consumido
    e o streak é mantido. Exibir ícone de escudo na HomeScreen.

---- TÉCNICO ----

[ ] Migração de dados local → conta
    Se o usuário usou o app como convidado e depois cria conta,
    os dados do AsyncStorage são perdidos. Implementar migração
    automática: ao fazer login/cadastro, verificar se há dados
    locais e perguntar se quer importar para a conta.

[ ] Tratamento de erros mais visível para o usuário
    Atualmente os catch blocks apenas retornam false/[].
    Adicionar feedback visual (toast ou alert) quando uma
    operação falha, especialmente ao salvar registro.

[ ] Offline-first melhorado
    Quando sem internet, operações no Firestore falham silenciosamente.
    Implementar fila local: salvar no AsyncStorage e sincronizar
    quando a conexão voltar. Firestore SDK tem suporte a isso
    com enablePersistence().

[ ] Testes básicos nas funções de cálculo
    calcStreak(), recalcEconomy() e checkAchievements() são funções
    puras (ou quase) que podem ser testadas com Jest sem precisar
    de device. Adicionar ao menos testes das condições de borda
    (streak zerado, economy sem device, etc).
